# nuxt-ai-chatbot — risks and open questions

| ID | Risk | State | Notes |
|---|---|---|---|
| NC-A | `baseline-v1` is not yet proven live | OPEN | Proven offline in Baseline CI: the offline bootstrap with the blueprint's own hooks, the lanes' own steps in staged job trees (the migrations applied through a stand-in D1 API over real SQLite), the built Worker served by `wrangler dev` — migrated, a chat streamed through a Workers AI stand-in and persisted, an upload signed in to R2 and back, the owner's secrets connected |
| NC-B | A real Workers AI answer is not exercised offline | OPEN | Workers AI has no local mode; the stand-in answers the binding's shape. Kimi K2.6 and GLM 4.7 Flash are ai-chatbot's choices; the first live build proves they answer with tools and streaming |
| NC-C | `workers-ai-provider` is deprecated | WATCH | Every version is marked deprecated in favour of `agents/models/ai-sdk`'s `createAI`, which is built around the AI Gateway. It works on the binding, as ai-chatbot's does; move when the replacement drives the binding without a gateway |
| NC-D | The template moves on `main` | ACCEPTED | The repository has no tags; this port is `main` at `3891852`, every dependency pinned to that lockfile's resolution, and a bump is a deliberate change |
| NC-E | Dictation and web search need the AI Gateway | ACCEPTED | Both are the gateway's (its transcription model, the providers' search tools); they appear with its key and are hidden without it |
| NC-F | Uploads are public by URL | ACCEPTED | As upstream's Vercel Blob URLs were: `/api/files/<username>/<chat id>/<name>-<random>` is the capability. Only signed-in users upload |
| NC-G | The session key lives in the database | ACCEPTED | Generated by `020_app_secrets`; anyone who can read D1 can read it — the same boundary as the chats it protects. An Orun secret overrides it |
| NC-H | Icons not in the scanned bundle | WATCH | Every literal icon name in `app/` and `shared/` is bundled; a name built at runtime would fall back to Nuxt Icon's remote collections, a CDN fetch on the Worker |
| NC-I | nuxt-csurf's encryption secret is per build | ACCEPTED | Upstream's behaviour: generated at build, baked into the runtime config; CSRF tokens issued before a deploy stop validating after it |
| NC-J | AbortSignal over RPC in the e2e | ACCEPTED | The chat passes an AbortSignal to its model; the real binding takes it, and the e2e's stand-in is reached over RPC with `enable_abortsignal_rpc` set in the e2e's config only |
